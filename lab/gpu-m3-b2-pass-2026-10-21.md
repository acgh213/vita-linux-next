# M3-B2 — first standard-ABI modeset and page flip: PASS

## Claim boundary

On the PSTV, one raw-ioctl userspace program successfully enabled the inherited fixed-mode
DRM CRTC, presented an initial grey framebuffer, then requested one magenta page flip.
The selector readback toggled for both commits, the matching DRM event arrived within five
reported frame periods, and scanout position advanced afterwards. Cleanup left the logical
CRTC inactive with no pending flip; SSH remained usable. No new dmesg lines appeared during
the successful probe (pre/post kernel-message comparison).

This is **M3-B2 PASS**, not completion of the M3 lane: sustained cadence (C), forced-exit/reboot
lifecycle (D), and framebuffer-console takeover (E) remain untested. There was no independent
human observation of colour or tearing. This is register/event evidence, not visual proof or
SGX/3D acceleration. The experimental branch still has no fbcon framebuffer.

## Source review changed B1 before the test

The original `e2991711` wiring was not safe despite compiling. Source review identified missing
event locking/reference ownership, racing target/event publication, fake-vblank completion
mixed with real flips, stale partial-damage contents across ping-pong buffers, and absent
producer-side ordering for write-combined pixel stores. The earlier boot never exercised a
userspace commit, so it had not validated any of those paths.

Correction `4c46f62c3178` full-copies into the inactive buffer, executes producer-side `wmb()`,
and publishes target/event/reference together under an IRQ-safe lock. First-enable publication
waits for DRM vblank-on; disable drains it. ISR switches/readbacks the explicit target, accounts
vblank, and completes the associated event with balanced ownership. The side-effecting debugfs
`flip` file was removed. `iftu_state` now snapshots selector and cached state coherently, and
reports the decoded scanline. Probe guards reject unverified inherited geometry/state before
register writes.

An independent second reviewer approved this scoped serial fresh-boot test. This is not a
claim of general recovery from concurrent helper dependency timeouts, framebuffer takeover,
or arbitrary modes. Driver `W=1` object build emitted no warnings.

## Instrument errors retained, not hidden

- `attempt-01-discovery`: stopped before buffer allocation or modesetting because the probe's
  first GETCONNECTOR request supplied a nonzero mode count. That bypasses the core's initial
  `fill_modes` call. Fixed by zero-count discovery followed by a fetch.
- `attempt-02`: discovery found one connected mode, but fetch returned EFAULT. The discovery
  call also returned a property count; retaining that count without property-array pointers
  requested an invalid copy. Reset the unrequested property count before fetch.
- Neither attempt issued SETCRTC or PAGE_FLIP. Selector remained zero, no flip pending.
- The mock now models both zero-count mode discovery and property-count/pointer interaction;
  the previous mock was too permissive. Ten host control-flow/evidence-judging tests pass.

## Successful attempt 03

The connector supplied 1280×720, pixel clock 64,473 kHz, totals 1650×750. Two separate
3,686,400-byte dumb buffers (stride 5120) became framebuffer IDs 38 and 39.

1. Before modeset: selector=0, cached=0, pending=0, hardware vblank count=22650.
2. SETCRTC with grey buffer succeeded. Before the flip: selector=1, cached=1, pending=0,
   hardware vblank count=22653.
3. PAGE_FLIP to magenta requested a completion event. Correct cookie/CRTC/type returned,
   DRM sequence=5, elapsed=49,589,437 ns (49.589437 ms), against a 95,970,407 ns budget.
4. Immediately afterwards: selector=0, cached=0, pending=0, hardware vblank count=22656.
   Thus the flip interval advanced three raw hardware vblanks, within the five-frame gate.
5. Scanout-byte samples after the flip: 1280 → 2632960 → 1092608. The selector stayed zero
   throughout the extra samples. The nonmonotonic byte position is expected across frame wrap.
6. Probe exited zero after disabling its CRTC and releasing its buffers. Independent post-read:
   CRTC enable=0, active=0; pending=0; selector and cached state both zero. SSH still responsive.

`tools/check-drm-flip.py` returned PASS from the saved successful transcript. The uploaded probe
hash was verified remotely before execution; the kernel identity and remote process exit status
were checked separately. Test fixtures are not included in the hardware evidence directories.

## Next boundary

M3-C must measure repeated flips, not extrapolate from this one: the successful call took about
50 ms, which does not establish one flip per 19.2 ms frame. Full CPU copies may limit throughput.
Keep E deferred until the presentation path has stronger lifecycle evidence. Production main's
kernel pin remains unchanged; experimental work is proposed separately, not silently deployed
as the default.
